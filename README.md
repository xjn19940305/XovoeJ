# XovoeJ

一个面向单商户 B2C 场景的电商系统项目。

这个仓库的目标不是只做一个“下单商城”，而是把一个完整的电商后台逐步收口成可持续演进的业务系统，包括商品、交易、资产、会员、营销、增长、消息、内容与权限体系。

## 项目定位

XovoeJ 聚焦于这类问题：

- 后台模块很多，但权限、接口、菜单、按钮各写各的，难以统一管理
- 订单、支付、库存、售后、资产之间边界混乱，后期越改越重
- 优惠券、活动、分销、消息通知分散在不同模块里，缺少统一抽象
- 管理端可联调，但缺少长期可扩展的领域结构

这个项目希望把这些问题拆开重建，形成一套更清晰的电商业务骨架。

## 核心能力

当前仓库围绕以下业务中心设计和实现：

- 权限与接口体系
  - 统一 `permission code`
  - 管理端 / 商城端 / 集成端分层
  - 菜单、按钮、接口共用一套权限语义
- 商品与交易
  - 商品、分类、SKU、订单、购物车、结算
  - 支付单、发货、签收、取消、售后
- 资产与会员
  - 优惠券账户
  - 钱包账户与流水
  - 积分账户与流水
  - 会员等级与会员中心基础能力
- 营销中心
  - 优惠券
  - 营销活动
  - 秒杀 / 拼团 / 砍价等高级营销骨架
- 增长中心
  - 邀请关系
  - 推广链接
  - 佣金记录与结算管理
- 消息中心
  - 消息模板
  - 消息任务
  - 发送记录
- 内容与系统管理
  - 轮播图
  - 工作流
  - 角色、权限、用户、字典等后台管理能力

## 这个仓库在做什么

如果用一句话概括：

> 这是一个正在持续重构中的电商业务系统，重点不是“把页面补齐”，而是把后台、API 和业务底座重新整理成可长期维护的结构。

它更偏向下面这类仓库：

- 有明确业务分层的电商中后台
- 以管理端和 API 为主线推进
- 逐步把营销、资产、履约、增长、消息纳入统一体系

而不是：

- 只展示商城首页和商品详情的演示项目
- 只做前端页面效果的模板仓库
- 只有 CRUD，没有业务状态和领域边界的练手项目

## 架构特点

- 单商户标准 B2C
- 后端采用分层结构：
  - `Domain`
  - `Application`
  - `Infrastructure`
  - `XovoeJ.Api`
- 前端采用独立 `ClientApp`
- API 边界按业务入口拆分：
  - `api/admin/*`
  - `api/mall/*`
  - `api/integration/*`
- 权限统一使用点分式编码，例如：
  - `admin.product.read`
  - `admin.coupon.issue`
  - `mall.order.create`
